继续使用 wzt.hk，补齐服务器执行程序即可。当前最先需要处理的是代码、部署和文档之间的不一致，其次才是 NTULearn 文件同步和学习资料生成。不要再新建一套网站、通用 Agent 平台或独立知识数据库。

## 3. 可复用的现有能力与边界

### 网站与知识库

- 复用 `src/server/database.ts` 的笔记读写、`/admin/kb` 编辑页、`/kb` 阅读页、分类、标签、Markdown 和目录。
- 复用后台登录、会话、CSRF 与来源校验。`strict` 是 AI 写作模式，不是访问控制字段。
- 现有搜索主要是标题、摘要、标签等元数据过滤，并非全文或语义搜索。
- `draft=1` 能让笔记退出公开列表和详情，适合作为短期默认；长期应区分“私有资料”和“尚未发布的草稿”，增加受保护的课程阅读页。
- 笔记创建 API 省略 draft 时会得到公开笔记。自动导入必须明确私有，不能依赖现有默认值。
- 当前 Markdown 页面直接渲染解析结果；引入外部资料/自动生成内容前需做 HTML 与链接清理，不能只信任模型输出。
- 当前未发现公式渲染组件。课程材料需要补数学公式显示、来源文件链接和页码/幻灯片引用。
- R2 可继续使用；现有 `/media/` 用来公开读取 `public/` 对象，不可把学校原件直接放入该前缀。课程文件用私有前缀或私有桶，加后台授权下载。

### NTU 通知原型

本地 `src/server/ntu/` 已有：BbRouter 凭据加密、课程选择、公告/日历分页读取、内容指纹、首次同步基线、D1 同步锁、通知 outbox、退避重试、每天普通消息汇总、重要事项通知、24 小时内日历提醒、GLM JSON 摘要及失败降级。配置入口为 `/admin/ntu`。

它还没有：递归课件目录同步、附件下载和版本管理、完整 Assignment 识别、PDF/PPTX 解析、学习材料生成、笔记与原件关联、Telegram 决策回调、外部日历创建、通用任务运行历史。

当前 `ntu_state` 记录最近状态，`ntu_delivery` 记录通知投递；二者不能替代完整的每次任务执行历史。当前 GLM 只处理短公告摘要，不是课程分析服务。

### PR #3 的知识库原型

已实际阅读该分支的 schema、GLM 客户端、抽取与队列脚本。可以保留原始材料、来源、处理版本等设计，但应修改后再用：

1. `0015_kb_overlay.sql` 与已应用的 `0015_ntu_notifications.sql` 重号。不要重命名已执行迁移；未来 overlay 使用新编号。重号不必然意味着工具拒绝执行，但会造成迁移排序与维护歧义。
2. `kb_sources` 只按 source_type/source_id 唯一，没有完整不可变版本历史；不能仅凭“冻结快照”的注释认定版本追踪已完成。
3. 队列按已完成任务和 processor_version 去重，没有把源文件 hash 纳入完成判断；原资料更新后可能不重新处理，未完成任务也可能重复排队。
4. 没有稳健的任务租约、进程崩溃恢复和原子提交；多阶段抽取中途失败可能留下部分结果，再运行可能追加重复内容。
5. FTS 索引只有插入/删除触发器，没有更新触发器；中文检索效果需要另测。
6. 当前 runner 使用本地 node:sqlite，不是 D1 远程执行器。分支状态文件声称的 snapshot 阶段未见独立实现，只有 smoke 脚本中的小样本插入。
7. GLM 客户端直接从 `~/.claude/settings.json` 取密钥并发 HTTP 请求，注释将其视为 Coding Plan 已覆盖；这一推断没有充分依据，不能直接用于长期服务。

第一阶段不需要把实体图谱、别名消歧、Vectorize、全站 RAG 全部做完。课程资料与复习笔记的可靠闭环更优先。

## 4. NTULearn 上游项目评估

上游为 Python 3.12+ 的 stdio MCP，提供课程、目录、公告、日历、成绩簿和附件工具；底层 `BbClient` 可以被普通同步程序复用，不必为了定时下载每次启动 LLM。保留 MIT 许可与来源。

它不是完整的无人值守同步器。Cookie 失效后只重新解析本地凭据并重试一次，不具备 SSO/MFA 自动续期；重复下载使用文件名后缀避免覆盖，不能充当增量版本管理；小文件读取限制为 1 MB，扫描件也没有自动 OCR。

接入前需修正的具体问题：HTML 附件链接没有限定来源域，文件客户端会给传入 URL 附加 BbRouter；还启用了自动重定向。应限制可信来源与重定向链，外部链接不携带学校 Cookie；分页设上限与循环检测；下载流式写入、限制体积、验证类型、避免把登录 HTML 当作 PDF；失败的附件列表读取不能静默标记为完整同步。

Linux 无桌面凭据库时，使用服务账号专属的受保护凭据文件或 systemd 凭据。不要要求服务器读取 Windows 浏览器；先验证一门课，确认 Cookie 在 VPS 出口 IP 下有效。真实 Cookie 寿命只能运行后观察，不预设固定天数。

## 5. GLM 和开发工具的分工

把“执行工具”与“底层模型”分开：本机 Claude Code 已配置为调用 GLM，所以 Claude Code 并不必然代表 Claude 模型。Muse、Claude Code、Codex 也不应轮流重复阅读同一批课件。

| 组件 | 建议职责 |
|---|---|
| Muse | 理解需求、选择任务、解释重要变化、接收用户决策、发起分析或开发任务 |
| 普通服务器程序 | 定时扫描、下载、指纹去重、解析、任务锁、重试、状态和日志 |
| GLM | 讲解课件、归纳重点与公式、生成自测与答案解析；处理有引用的内容 |
| Codex / Claude Code | 修改代码、排错、测试、维护部署；不参与每轮机械扫描 |
| D1 + wzt.hk | 元数据、任务状态、笔记与管理/阅读界面 |
| VPS 磁盘 | 原文件工作副本、解析中间文件、受限并发执行 |
| 私有 R2 | 原件/产物备份及按需下载，避免 VPS 成为唯一副本 |
| Telegram | 有意义的变更提醒、决策按钮或命令；与 Muse 协调唯一的消息接收者 |

智谱官方当前说明：Coding Plan 只覆盖指定工具/产品环境；不能把自建脚本对某兼容 endpoint 的 HTTP 调用自动认定为套餐内。官方支持列表包含 OpenClaw，但 Muse 是否属于该环境尚未核实，调用成功也不能单独证明用量规则。

建议 GLM 接口做成一个很薄的可替换调用层。无人值守课程流水线暂按通用 API 计费规划，先测试一份课件、核对账单，再确定每门课/每日预算。若 Muse 的实际运行环境符合官方套餐要求，再选择其受支持的调用方式。开发任务继续使用现有 Claude Code/GLM 配置。不要用换 endpoint、伪装工具等方式假定绕过限制。

Codex 的 `codex exec` 和 Claude Code 的 `claude -p` 都提供程序化调用与结构化输出能力；这证明存在轻量 CLI 连接方式，但不证明 Muse 已能调用本机程序或 VPS。配置检查未启动任何额外模型任务。

## 6. 连接方式：先选最短路径

| 场景 | 起步方案 | 何时才增加组件 |
|---|---|---|
| Muse 能在 VPS 执行命令 | 调用固定 CLI：同步、列任务、分析、重试 | 无需额外 HTTP 服务 |
| Muse 有 SSH 能力 | SSH 执行上述 CLI，返回 JSON 和任务 ID | 无需为 SSH 再建通用 Agent API |
| Muse 只支持 MCP | 给相同业务函数加很薄的 MCP 适配层 | MCP 作为工具入口，不承担定时调度 |
| Muse 只支持远程 HTTPS | 为必要动作加受认证接口 | 只开放任务级动作，避免通用 shell/任意 SQL |
| VPS 写入现有网站 | 小样本可用受控导入；无人值守评估直接 D1 API 或现有 Worker 增加少量任务接口 | 根据权限范围选择，不另建一套网站服务 |

**暂定倾向**：D1 保持业务与任务状态的权威来源，VPS 做执行端，文件在 VPS 工作并备份到私有 R2。这样网站原生看得到任务，不需要把 D1 和另一套服务器业务库做双向同步。

直接通过 Cloudflare API 使用 D1 可以少写接口，但授权粒度可能覆盖账户下多个 D1，需核实 token 实际作用范围；不能承诺它天然限制到某几张表。若因此权限过大，在现有 Worker 内加“领取任务/提交结果/查询状态”等少量接口反而更简单可控。API 只做短事务，长时间文件/模型处理由 VPS 完成。现有后台 Cookie+CSRF 保留给交互操作，不把管理员会话复制为长期服务凭据。

如果最终选择 VPS SQLite 为队列权威，也可行，但 D1 只保留展示投影，不能让两边都独立修改同一任务；目前没有必须采用这一方案的依据。

定时器按工作流单一归属：已恢复的通知模块可暂留 Cloudflare Cron；新文件分析用 systemd timer/服务。若日后将 NTU 扫描整体搬到 VPS，应同时关闭旧扫描入口，避免两个系统重复提醒。初期不要引入 Redis、Celery、Kubernetes。

## 7. 第一阶段实施与验收

### 0：恢复可维护的代码基线

- 保存现有未提交成果，与真实远程 main 做受控整合，保留今天航班改动。
- 明确 NTU、PDF 配置哪些应进入仓库；对关闭的 PR 挑选可用内容，不盲目重开并整体合并。
- 修正“preview 即隔离环境”等过期文档。生产迁移记录和线上资源为依据，不导入旧本地数据库覆盖生产。
- 明确真正的测试 Worker、D1 与 R2 隔离边界；部署前备份，并保留可回退版本。

验收：仓库里的一个明确提交能复现待部署内容，NTU 页面恢复后可登录访问，非登录访问仍受保护。

### 1：一门课的增量同步

- 用户提供有效 Cookie，先只读验证课程目录、一个 Assignment、一个 PDF/PPTX 附件。
- 普通程序递归读取目录，以学期/课程/content_id/attachment_id 标识资源；保存来源 URL、更新时间、大小和 hash。
- 用更新时间、ETag/Last-Modified（上游支持时）减少重复下载，必要时校验内容 hash；周期性复查同名替换，不能只比文件名。
- 原件使用版本化路径，下载临时文件成功后原子改名；未完整扫描的轮次不推进成功游标。
- 首轮建立基线，历史文件可以限量回填，但不发送一串旧通知，也不默认对所有历史文件调用 GLM。
- Cookie 失效记为 `needs_auth`，合并提醒并暂停相关请求；更新 Cookie 后续跑。普通网络/限流错误退避重试，达到上限才提醒。

验收：连续两轮无变化时不重复下载/建任务；同名文件更新产生新版本；认证过期与重启不丢进度。

### 2：文件分析与私有笔记

- PDF/PPTX 优先本地提取文字并保留页码/幻灯片号；无有效文本时 OCR；复杂图表和公式只把需要的页面交给具有相应能力且账号可用的模型。
- GLM 产出详细讲解、重点、公式（含变量与适用条件）、自测题、答案解析和复习提纲；按长度拆分再汇总，检查覆盖页数。
- 原文结论与补充讲解分开标明；未知信息保留未知，所有重要结论能回到来源页。
- 幂等键包含 source_id、source_hash、任务类型、processor_version 和必要的模型配置；保存模型、提示模板版本、耗时、用量、错误、尝试次数和生成时间。
- 完整生成并通过格式/引用校验后再提交新版本；失败不覆盖上一份可读笔记。
- 扩展现有 kb_notes 与私有阅读页，增加来源/产物关联。任务字段保持通用，课程专属字段放连接器元数据，后续论文/研究可复用。

验收：一份真实课件生成可读笔记和自测题，公式显示正常、引用能回到原件；断网与模型失败可重试；自动产物不出现在公开知识库。

### 3：Assignment 互动与低打扰运行

- Assignment 从内容类型、附件说明、日历和必要的 gradebook 元数据交叉识别；日历没有记录不等于没有作业。
- 首次发现推送要求摘要、明确截止时间及来源，并询问是否深入分析/加入日历。没有明确截止日期就写“未说明”，模型推测不直接生成提醒。
- 日期标准化为 UTC，并在界面按 Asia/Singapore 显示；日期变更和取消更新已有提醒/日历事件，不新增重复项。
- 普通资料按日汇总，重要截止变更及时通知；无需决策且没有变化时保持安静。
- Telegram 接入先确认是否已有 Muse bot。同一个 bot 的 getUpdates/webhook 消费者应统一管理，不额外创建冲突的轮询器。校验允许的 chat_id；按钮回调幂等处理。
- 日历先可生成 ICS，用户确认后再接其实际使用的日历服务。不要为尚未选择的日历预装插件。

验收：真实运行至少一周；通知不重复刷屏；进程重启、Cookie 失效、模型/网络失败均保留任务记录；人工确认才触发所请求的深入分析或日历动作。

| GitHub | 连接器和 gh 可读指定仓库、PR、分支 | 调查无需新增权限；需要推分支/PR 时核实该仓库写权限，Muse 不必获得全账户权限 |
| Cloudflare | 本机 Wrangler OAuth 可用，已只读检查 Worker/D1；已有较广写 scopes | 本轮无需重新登录；VPS 长期服务使用单独凭据，按 D1/R2/必要 Worker 操作限定，避免复制桌面 OAuth |
| VPS | 未核实 | 提供主机或 SSH alias、端口、普通用户；通过 CloudCone 控制台添加执行端 SSH 公钥，私钥留在执行端。先确认主机指纹，再查系统/容量/服务，不先停现有服务 |
| Muse | 身份与运行位置未明确 | 提供产品/仓库链接或本地目录、运行主机及当前 GLM/Claude Code 调用方式；不提供秘密值 |
| NTULearn | 无课程连接配置和同步记录 | 在受保护的设置页或服务器凭据入口录入 BbRouter；不要发聊天正文或提交 Git |
| GLM | 本机兼容配置存在；通用 API 可用性与余额未测 | 确认国内智谱或其他平台、套餐/通用余额、可用模型和预算，在受保护入口设置工作流凭据并做一个最小测试 |
| Telegram | NTU 设置为空，未测试消息 | 确认已有 bot 归属；必要时 BotFather 创建私人 bot、发 /start，设置允许的聊天，之后显式做测试消息 |
| 日历 | 尚未指定 | 等用户选择实际日历后按需授权 |

不需要一开始开放 CloudCone 管理 API、全局 Cloudflare API Key、root SSH 或全盘 NAS 权限。日常同步/分析/重试按已设规则自主执行；新凭据授权、正式部署/迁移、不可恢复删除或对外公开内容保留明确确认点。凭据与备份分开保存，任务日志不记录 Cookie、Token 或模型请求头。
